Timing is how long a motion takes. It is the first thing the eye reads, and it reads it before it reads anything else. A slow move feels heavy or important. A fast one feels light or trivial. Nothing else about the motion has to change.

<Beat kind="see">One move, four lengths</Beat>

The same dot crosses the same distance four times. Only the time it takes changes. Watch each row and notice what it seems to *be*.

<Beat kind="more">The bands</Beat>

<Margin kind="history">
  <p>Jakob Nielsen's response-time limits (1993): about <b>0.1s</b> feels instantaneous, about <b>1s</b> keeps the flow of thought, <b>10s</b> loses attention. They still hold.</p>
</Margin>

Most interface motion lives in four bands. Learn how each one *feels*, not just its number.

- **About 100ms: instant.** Press states, toggles, checkboxes. Faster than this and the motion isn't seen at all; slower and the control feels laggy.
- **About 200ms: quick.** Hovers, tooltips, small reveals, menus. Seen, but never waited for.
- **About 300ms: considered.** Panels, cards, dialogs. Enough time to show where something came from.
- **About 500ms: deliberate.** Big scene changes, onboarding, a page turning. Use it rarely. If people see it every minute, it will start to feel slow.

This app uses exactly these bands as its tokens: `--dur-instant` 90ms, `--dur-quick` 180ms, `--dur-base` 280ms, `--dur-scene` 480ms.

<Beat kind="more">See in frames</Beat>

The web measures time in milliseconds. The screen shows it in frames. A 60Hz display draws a new frame every 16.7ms, so:

| Duration | Frames at 60Hz | Frames at 120Hz |
|---|---|---|
| 100ms | 6 | 12 |
| 200ms | 12 | 24 |
| 300ms | 18 | 36 |
| 500ms | 30 | 60 |

Animators think in frames because frames are what you actually see. A 100ms move is six drawings. That's why it barely registers: there aren't enough drawings to show a path. When a motion feels "jumpy", count its frames. It usually has too few for the distance it covers.

<Figure n="2.2" caption="Distance changes the right duration">
  <SpacingChart rows={[
    { label: "short · 300ms", duration: 300, to: 80 },
    { label: "long · 300ms", duration: 300, to: 480 },
    { label: "short · 180ms", duration: 180, to: 80, tone: "blue" },
    { label: "long · 380ms", duration: 380, to: 480, tone: "blue" }
  ]} easing="--ease-out" />
</Figure>

A duration is not "right" on its own. The top two rows share 300ms. The short move dawdles; the long one rushes, with gaps so wide the eye loses the object between frames. The blue rows fix both: shorter for the short trip, longer for the long one. Duration should grow with distance, but more slowly than distance does.

Size works the same way. A large panel sliding in needs more time than a small chip, because more of the screen changes.

<Beat kind="tune">Change one thing: duration</Beat>

Drag the duration and watch the frame count. Find where the move stops feeling like a *flick* and starts feeling like a *journey*. Then change the frame rate to 12: this is "animating on twos", the way hand-drawn films save drawings.

<Beat kind="write">The notation</Beat>

Now the numbers. In CSS, duration is `transition-duration` or `animation-duration`, in `ms` or `s`. Keep durations in tokens, so a whole app shares one sense of time.

<div class="snippets">
<Snippet title="02 · Timing: durations as tokens" lab="spacing-chart" easing="--ease-out" duration={180} distance={240}>

```css
:root {
  --dur-instant: 90ms;   /* press, toggle */
  --dur-quick:  180ms;   /* hover, tooltip, menu */
  --dur-base:   280ms;   /* panel, card, dialog */
  --dur-scene:  480ms;   /* page, onboarding */
}

.menu {
  transition: opacity var(--dur-quick) ease-out,
              transform var(--dur-quick) ease-out;
}
```

</Snippet>

<Snippet title="02 · Timing: duration grows with distance" lab="spacing-chart" easing="--ease-out" duration={380} distance={480}>

```js
// Longer trips get more time, but not proportionally more.
function durationFor(distance, base = 180, per100px = 45, max = 480) {
  return Math.min(max, base + (distance / 100) * per100px);
}

panel.animate(
  [{ transform: 'translateX(100%)' }, { transform: 'none' }],
  { duration: durationFor(panel.offsetWidth), easing: 'ease-out' },
);
```

</Snippet>
</div>
